01 — CORE IDEA

〈 HOW IT WORKS 〉

One giant world element with translate + scale. Cards store world coordinates; SVG arrows live inside the same transform so they pan/zoom with you.

CONCEPT 01
🗺️

Infinite Canvas

world.style.transform = translate(tx,ty) scale(s) moves one container. Cards never move for navigation — the world does.

translate + scale
CONCEPT 02
🔍

Zoom-to-Cursor

Clamp new scale, compute ratio r, adjust tx = cx - r*(cx - tx) so the point under your mouse stays fixed.

zoom math · interview fav
CONCEPT 03
🌐

Wikipedia CORS

Browser calls Wikipedia directly with origin=* (permissive CORS header) — no server proxy. fetch + async/await.

fetch + origin=*
CONCEPT 04
🛡️

XSS-Safe Content

Article HTML parsed with DOMParser inertly, paragraphs extracted, all tags stripped except <strong> and <br> before innerHTML.

sanitize · security
CONCEPT 05
↗

SVG Connections

Arrows drawn as SVG paths inside the world so they inherit the transform. Curved/straight/stepped + dashed/open/no-arrow styles.

bezier · SVG marker
CONCEPT 06
🔄

CRDT Board Sync

Operations (createNode, addConn…) are LWW CRDT ops with lamport clock. syncMerge deduplicates and re-applies missing ops for multi-peer sync.

CRDT · opLog

⧩ ARCHITECTURE ⧩

Single-file 1089-line prototype refactored to modular UMD + Worker + Viz + library + tests — same pattern as Compiler Forge & Logic Forge.

Module Map

 index.html  → loads style.css + lab.css (Y2K + paper board)
            ↳ wiki-engine.js  (UMD: browser / Worker / Node)  — WORLD/COLS, setOf/addAll, esc/sanitizeContent, worldToScreen/screenToWorld, c2w/w2c, zoomTransform, computeFit, portAnchor/bestSides/mkPath, Wiki URL builders, board state (Map+Array), CRDT opLog + vectorClock + syncMerge
            ↳ wiki-worker.js  (Web Worker) — importScripts(wiki-engine.js), onmessage {sanitize|portAnchor|mkPath|createNode|applyOp|merge|computeFit|wikiUrls|ping}
            ↳ viz.js          (UMD) — esc() XSS-safe, buildNodeSVG / buildStickySVG / buildConnectionSVG / buildBoardSVG (dot grid, minimap-aware)
            ↳ wiki-library.js (UMD) — boards: philosophy_map · science_overview · history_timeline · tech_stack · art_movement · empty_starter
            ↳ app-integration.js — Worker lifecycle + sanitizeAsync / syncAsync + loadExampleAsync (WikiLibrary→WikiEngine)
            ↳ script.js       — board UI: G state (Map-backed), infinite canvas via CSS transform, zoom-to-cursor, Wikipedia fetch (origin=*), safe rendering, ports/connections, stickies/texts/images/groups, generic drag, canvas events, toolbars, search + autocomplete, keyboard, minimap, menus, save/load, integration hooks (uses WikiEngine if present)
 tests/run-tests.js → wiki-engine.test.js + viz.test.js (Node assert, proof of CRDT, transforms, XSS)

File-by-File

wiki-engine.js — Core truth. WORLD/COLS, setOf/addAll, esc/sanitizeContent (regex + allow-list), worldToScreen/screenToWorld/c2w/w2c, zoomTransform (tx = cx - r*(cx - tx)), computeFit (bbox → scale/tx/ty), portAnchor/bestSides/mkPath (SVG bezier), buildSearchUrl/… (pure URL builders), board state Map(nodes)+Map(conns)+Map(stickies)…, boardCreateNode/addConn… (each emits CRDT op), createOp/applyOp/mergeOps/syncMerge (LWW + lamport), serialize/deserialize, UMD wrapper.
wiki-worker.js — Offloads sanitization & CRDT. importScripts('wiki-engine.js') try/catch, onmessage handles sanitize/esc/portAnchor/mkPath/createNode/applyOp/merge/computeFit/wikiUrls/ping, timeout fallback in app-integration.
viz.js — XSS-safe SVG. esc(), buildNodeSVG (paper card + ports), buildConnectionSVG (bezier + marker), buildBoardSVG (bounds → dot grid + wires behind nodes + footer), drawMinimapCanvas (canvas minimap), UMD.
wiki-library.js — Declarative boards. Each has nodes{title,x,y,w,h,colIdx}[] + conns{from{idx},to{idx},style,label}[] + stickies/texts. Helpers get/list/injectExample/instantiate(WE) mirroring logic-library.js.
app-integration.js — Bridges UI↔engine↔worker. initWorker (require http, not file:), workerExec promise map + 2.5s timeout, sanitizeAsync/syncAsync with main-thread fallback, loadExampleAsync(state) via WikiLibrary + WikiEngine.
script.js — The board lab. G now backed by Map but wrapped for legacy DOM access; uses WikiEngine if present for esc/sanitize/mkPath/bestSides/world↔screen, otherwise inline fallback; keeps all original features (search+AC, wSearch/wSummary/wImages, mkNodeEl/hook, renderContent sanitised, collapse/cycle, loadRelated, drag/resize/ports, connections SVG inside world, stickies/texts/images/groups, canvas pan/zoom/minimap, toolbar, menus, keyboard, save/load, export JSON/SVG via Viz).
index.html / style.css / lab.css — Y2K maximalist shell (glitterCanvas, bgCanvas, ticker, cyber-nav, hero with terminal typewriter, token-strip, section-containers, lab flex). lab.css holds simulator layout + full paper-board styling (node/port/sticky/topbar/mmap/menus/toast).
tests/ — Node proofs: wiki-engine.test.js checks UMD, esc/sanitize, transforms/zoom, port geometry, URL builders, board CRUD + dedup, CRDT apply/merge, serialize, COLS; viz.test.js checks esc and SVG builders XSS-safe.

Interview Guide

30-sec pitch: “WikiBoard is an infinite-canvas research board. You search Wikipedia, drag articles as cards, click links to spawn related cards, draw arrows — all in one world element moved via translate+scale. It talks to Wikipedia straight from the browser with origin=*, sanitises HTML via DOMParser + allow-list, and syncs ops via a tiny CRDT so two peers can merge boards.”

Q: How does the infinite canvas work? A: One world div with transform = translate(tx,ty) scale(s). Never move cards for navigation — move one container. Cards store world coords; convert clicks with c2w = (cx - tx)/scale.
Q: Zoom toward cursor? A: Clamp scale, ratio r = new/old, shift pan so cursor point stays fixed: tx = cx - r*(cx - tx).
Q: Wikipedia CORS? A: Wikipedia supports anonymous cross-origin if you pass origin=*. So fetch works with no backend.
Q: XSS from Wikipedia HTML? A: Parse inertly, keep first 5 paragraphs >15 chars, convert <b>→<strong>, strip every tag except strong/br via regex, fallback escaped text.
Q: Connections stay attached? A: SVG layer lives inside world, so it scales/pans automatically. On drag we recompute endpoints via portAnchor + bestSides + mkPath.
Q: CRDT? A: Each mutation is an op with lamport clock. mergeOps deduplicates by id keeping higher lamport/ts; syncMerge applies missing ops idempotently — LWW for node fields.
Q: Scale to hundreds of cards? A: Cache API results, lazy-load images, virtualise off-screen cards (minimap gives overview) + cull renders.
